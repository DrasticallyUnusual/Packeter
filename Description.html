Overview

Modern software distribution is built on a Faustian bargain: every time you install a package, every pip install, every npm install, every git clone — you are opening a channel. Your IP, your machine fingerprint, your dependency graph, your development environment — all of it is logged, tracked, and profiled by centralized registries and package mirrors. The ecosystem has been engineered so that connecting is not optional. The convenience model is the surveillance model.

This is not paranoia. It is architecture.

Packeter is a cross-platform tool that downloads packages and dependencies via 14 package managers and generates install scripts for offline machines — without requiring you to reveal your hand to every registry in the chain. It provides a clean Tkinter GUI, auto-analyzes install scripts to resolve deep dependencies, and rewrites scripts to use local files instead of remote downloads.

The principle is simple: acquire what you need, offline, on your own terms. Download once, from a source you choose, on a connection you control. Then disconnect. The install script runs locally. No phone home. No telemetry. No dependency on services that do not serve you.

This is an initial step toward reclaiming the privacy that should never have been surrendered. Software freedom begins with the freedom to acquire software freely. Do no harm. Take no shit. Use responsibly.

Git

git clone — clones repositories with depth, branch, and tag support.

NPM

npm install — packs tarballs via npm pack without installing.

Pip

pip install — downloads wheels/sdists via pip download.

Cargo

cargo install — downloads crate source tarballs from crates.io.

Winget

winget install — downloads .msix/.exe/.msi via winget export/installer.

Chocolatey

choco install — downloads .nupkg packages for offline install.

Go

go install — downloads module source via go mod download.

Gem

gem install — fetches .gem files via gem fetch.

Docker

docker pull — pulls and saves images as .tar for offline loading.

Composer

composer require — downloads PHP packages via Composer.

APT

apt download — fetches .deb packages without installing.

DNF

dnf download — fetches .rpm packages without installing.

WSL

wsl --install — downloads WSL MSI and distro packages (.appxbundle).

Direct URL

https://... — downloads any file by URL, auto-detects install scripts.

Core Features

1. Smart Command Parsing

Paste any install command or URL into the source field. Packeter automatically identifies the package manager, extracts package names, flags, and versions. It supports complex commands including:

  • git clone --depth 1 --branch v2.0 https://...
  • pip install flask gunicorn --no-cache-dir
  • winget install --id Git.Git -e --source winget
  • wsl --install -d ubuntu
  • curl https://example.com/install.sh | sh (pipe install detection)

2. Pipe Install Detection

When a curl URL | sh or wget -qO- URL | bash pattern is detected, Packeter downloads the script first, then analyzes it for embedded downloads, and resolves those too. This handles most single-command install patterns used by project maintainers.

3. Script Analysis Engine

The analyzer parses shell scripts to extract download information at multiple levels:

  • Direct URLs — curl -O URL, wget URL
  • Variable assignments — VERSION="1.0", URL="https://..."
  • Function definitions — traces functions containing download calls
  • Function call tracing — follows calls like download_and_extract "$URL"
  • Template variable resolution — resolves ${ARCH}, ${url_base}, $1, $2 etc.
  • Multi-stage analysis — recursively analyzes downloaded scripts up to depth 3

4. Script Rewriting

After analysis, Packeter rewrites install scripts to replace remote downloads with local file operations:

  • curl URL -o file → cp "$_PACKETER_DIR/local" "file"
  • wget -O file URL → cp "$_PACKETER_DIR/local" "file"
  • pip install pkg → pip install --no-index --find-links=... pkg
  • npm install pkg → npm install ./downloads/pkg.tgz
  • Function overrides — generates replacement download_and_extract() that checks local files first, extracts with zstd/tar/unzip, and falls back to original curl

5. Install Script Generation

Generates ready-to-run install scripts in two formats:

  • .sh — Bash scripts for Linux/macOS (with error handling, set -e, colored output)
  • .bat — Windows Batch scripts (with @echo off, error codes)

Each script includes: file copy commands, extraction commands (auto-detected: .tar.zst, .tar.gz, .zip, .tar.xz, .deb, .rpm), and tool-specific install hints.

6. WSL Offline Support

Downloads WSL components for offline installation on Windows machines:

  • WSL MSI — fetches latest release from GitHub API (wsl.2.x.x.x64.msi)
  • Distro packages — downloads .appxbundle/.appx/.wsl for Ubuntu, Debian, Kali, openSUSE, SLES, Oracle Linux
  • Install hints — generates PowerShell Add-AppxPackage commands

7. Logging System

Two log files are maintained in the output directory:

FileContentFormat
Query.log Every command/URL submitted by the user YYYY-MM-DD HH:MM:SS - source command
Log.log Every successful file download URL - FileName - FileSize - Path - Date

8. Cross-Platform GUI

Built with Python's Tkinter (zero external dependencies). Features:

  • Dark theme with modern card-based layout
  • Real-time download status with colored log output
  • Scrollable job cards with per-download progress
  • Output folder selector with Browse dialog
  • Format selector (.sh / .bat) for install scripts
  • Supported tool tags for quick reference
  • Quit button for clean application exit

Key Technical Details

Zero Dependencies

Uses only Python standard library (Tkinter, urllib, subprocess, json, re, shutil, threading, dataclasses). No pip install required.

Threaded Downloads

Each download runs in its own daemon thread with queue-based GUI updates. The UI remains responsive during large downloads.

Depth-Limited Resolution

Script analysis recurses up to 3 levels deep to prevent infinite loops from scripts that download scripts that download scripts.

Variable-Aware Analysis

Resolves shell variables across scopes: positional parameters ($1, $2), local assignments, and global constants (ARCH, OS, VERSION) for accurate URL reconstruction.
